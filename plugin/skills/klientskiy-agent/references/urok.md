# Инструкция к уроку: что сделать, чтобы повторить

## Главное решение до всего остального

Собрать клиентского бота с нуля за 90 минут с группой новичков **нельзя**. Честный
хронометраж — 120 минут, и это без единого ЧП. Поэтому два рабочих формата:

- **Техчас накануне** (рекомендую): за день до урока — отдельная встреча на час, где
  поднимается сервер и ставится окружение. Вести его можно по чек-листу, без подготовки, и
  там же видно, кто не готов. Сам урок тогда укладывается в 90 минут и целиком про дело.
- **Два урока по 90**: «железо и бот» и «база знаний и выпуск».

Если всё же один урок — он будет 120 минут, и это надо сказать людям заранее.

## Что обещаем в начале, чтобы не ждали чуда

Скажите это вслух в первые пять минут, своими словами:

> К концу урока у тебя будет свой бот на своём сервере, который ответил **тебе** и соседке по
> потоку по скелету твоей базы. Ни одной цены он пока не назовёт — все строки стоят со «нет»,
> так и задумано. Бот, которого можно показать клиентам, получается после домашки: там ты
> дописываешь базу и подтверждаешь цены. Сегодня доводим до первого живого ответа, а ссылку в
> сторис ты поставишь не сегодня.

Это снимает и главный риск: кто-нибудь уйдёт с урока и выложит ссылку на сырого бота.

## Письмо за три дня — оно же допуск

Половина группы приходит неготовой, если просто «попросить подготовиться». Поэтому три пункта
ниже — **допуск к уроку**: сделала, прислала скриншот в чат, участвуешь.

### Допуск 1. Сервер отвечает без пароля

```bash
# на своём компьютере, в терминале
ls ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519 -C "moy-mac" -f ~/.ssh/id_ed25519 -N ""
ssh-copy-id -i ~/.ssh/id_ed25519.pub root@<IP сервера>    # спросит пароль root — он нужен один раз
ssh -i ~/.ssh/id_ed25519 root@<IP сервера> "uname -a"
```

Последняя команда должна ответить **без запроса пароля**. Скриншот этого вывода — ваш допуск.

> Зачем: все дальнейшие команды работают по ключу, а не по паролю. Пароль root понадобится
> ровно один раз, здесь.

### Допуск 2. На сервере стоит всё нужное

```bash
ssh -i ~/.ssh/id_ed25519 root@<IP сервера>
apt update && apt install -y curl git tmux python3 rsync
curl -fsSL https://deb.nodesource.com/setup_22.x | bash - && apt install -y nodejs
npm i -g @anthropic-ai/claude-code
curl -fsSL https://bun.sh/install | bash && echo 'export PATH="/root/.bun/bin:$PATH"' >> /root/.bashrc
exit
```

Зайти снова и проверить — должны ответить все четыре:

```bash
claude --version && bun --version && tmux -V && python3 -V
```

> Если `bun` не отвечает — выйдите и зайдите заново, путь подхватывается при новом входе.

### Допуск 3. Токен подписки получен

На **своём компьютере** (не на сервере): `claude setup-token`. Откроется браузер, войдёте,
вернётся длинная строка. Сохраните её в заметках — на уроке положим на сервер. **В чат эту
строку не присылать никому, включая меня.**

Там же напишите, какая у вас подписка: **Pro или Max**. На Pro не работает модель Opus, и
агент молча не поднимется — это надо знать заранее.

### Материалы, с цифрами

- прайс — не меньше пяти строк, как есть, без причёсывания;
- **двадцать скриншотов переписки с клиентами** или экспорт чата — оттуда берётся голос;
- три возражения **дословно**, как пишут клиенты, а не как вы их пересказываете;
- три настоящих вопроса клиентов — на них будем тестировать;
- чего у вас нет и что вы не делаете — пять пунктов;
- контакты, которые бот может давать, и решение про телефон: даём или нет.

### Восемь ответов — бриф

Пришлите одним сообщением, это ускорит урок на пятнадцать минут:
главный продукт · первый шаг, к которому ведём · главный вопрос клиенту · «ты» или «вы» ·
контакт для связи · сайт · телефон · какие цифры агенту запрещено называть.

### Ещё

- **Второй аккаунт Telegram** — второй номер, аккаунт мужа, подруги. Телеграм держит несколько
  аккаунтов на одном телефоне. С него напишете боту как клиент; без этого проверить нельзя.
- **Свой числовой id в Telegram**: напишите @userinfobot, он ответит числом. Запишите.
- **Если у вас Windows** — приходите на техчас, разберём отдельно: терминал и пути там другие.

## Урок, по блокам

### 0:00 · Зачем это и что получится (7 мин)

Показать **записью** (не вживую, чтобы не зависеть от сети): человек пишет вечером, бот
отвечает по делу, оставляет телефон, владелице падает заявка.

Сказать границу результата (текст выше) и границу продукта:

> Бот не закрывает сделку. Бот доводит до разговора и приносит телефон. Продаёте вы.

**Проверка понимания:** «напишите в чат одной фразой, что ваш бот делает и чего не делает».
Сразу видно, кто ждёт чуда.

### 0:07 · Создать проект (10 мин)

Проще всего — попросить Claude словами: «сделай бота для клиентов». Навык поднимется сам и
задаст вопросы. Команда напрямую, если хочется видеть механику:

```bash
python3 ~/.claude/skills/klientskiy-agent/scripts/new_agent.py \
  --slug <латиницей> --biz "<Название>" --owner "<Имя>" --city "<Город>" \
  --server root@<IP> --ssh-key ~/.ssh/id_ed25519 --model sonnet
```

Открыть папку и показать, что внутри: персона, семь заготовок, скрипты, каналы. Одной фразой
про каналы: «готового канала, который пускает незнакомцев, в Claude Code нет — этот написан
специально». Теорию не разворачивать.

### 0:17 · Бот в Telegram (12 мин)

Живьём у @BotFather: `/newbot`, имя, username, описание, аватар, `/setprivacy`. Сказать, что
**username выбирается один раз навсегда**.

Токен — на сервер командой с `read -s`: показать, что ввод не виден.

Второй бот — **для оповещений**: `/newbot`, имя «Заявки <бизнес>», написать ему «привет»
(бот не может написать первым), положить его токен и свой числовой id. Без этого «передам
владельцу» никуда не дойдёт, а проверка будет красной.

### 0:29 · База знаний — здесь происходит обучение (35 мин)

Самый длинный блок, и сокращать его нельзя. Заполняем **скелет всех семи файлов**: по одной
строке в каждый, из присланного брифа. Полноту — в домашку.

Остановиться на двух местах:

**Колонка «Называть»** у цен. Пока «нет» — бот цифру не произносит. И правило «от»: «от 4500»
со статусом «да» не бывает, человек услышит «4500», придёт, а выйдет 6000.

**Файл стоп-тем.** Чего нет — должно быть написано, иначе модель начнёт продавать по аналогии
с похожими бизнесами. Подсказка для заполнения: «о чём вас спрашивают, а вы отвечаете „нет, мы
такого не делаем“ — выпишите пять таких вопросов».

Голос: не описывать словами, а **скопировать десять своих сообщений** из переписки.

**Две минуты про персональные данные:** телефоны клиентов лежат у вас на сервере, оператор —
вы, бот не называет чужие данные в группе, по требованию человека его данные удаляются
командой `forget.py`.

**Проверка понимания:** «покажите свою строку цены и скажите, почему в ней стоит „нет“».

### 1:04 · Поднять и проверить (16 мин)

```bash
bash deploy.sh                                        # первый раз: только скопирует и скажет, что дальше
ssh -i ~/.ssh/id_ed25519 root@<IP> "bash /opt/<slug>/bin/install-server.sh"
bash deploy.sh                                        # теперь запустит и проверит
```

Пройтись по строкам проверки. Потом главное: **второй аккаунт, живой диалог на экране**.

> «Работает» — это не зелёная служба, а живой ответ с другого аккаунта.

**Контрольная точка:** «у кого зелёное, у кого красное — одной цифрой в чат».

### 1:20 · Домашка и вопросы (10 мин)

Раздать: запись урока, одностраничный чек-лист, ссылку на `podvohi.md`. Оставить минимум
восемь минут на вопросы — без них урок заканчивается скомканно.

---

## Если урок поедет — выбрасывать в этом порядке

1. Блок про тест двадцати четырёх вопросов — в домашку отдельным коротким видео.
2. Теорию про каналы и официальный плагин — одна фраза вместо объяснения.
3. Половину вступления: отличие от конструктора сжать до трёх фраз.
4. Заполнение файла возражений на уроке — оставить услуги, цены, воронку.

**Не сокращать никогда:** базу знаний и живой диалог со второго аккаунта. Это единственные два
места, где происходит обучение; остальное — установка.

## Как вести, чтобы не потерять группу

- **Правило трёх минут.** Одну ученицу при всех чиню не больше трёх минут, дальше — к куратору
  в личку. Иначе один сломанный сервер съедает весь блок.
- **Куратор в чате обязателен.** Урок с терминалом одним ведущим не ведётся: нужен человек,
  который смотрит скриншоты и отвечает, пока вы ведёте.
- **Три дорожки.** Объявить в начале: готовые идут по шагам; без сервера — садятся на
  запасной сервер и делают то же самое, свой переносят в домашке; без материалов — не трогают
  терминал вообще, весь урок пишут базу знаний в черновике и сдают её вместо бота. Третье —
  нормальный результат, и это надо назвать результатом вслух.
- **Что на экране:** терминал шрифтом 18+, тёмная тема; **телефон, выведенный на экран**,
  иначе финальный диалог никто не увидит; в блоке базы знаний — ваша настоящая переписка с
  заклеенными именами рядом с файлом голоса.
- **Чем занять паузы** (их три по 3–5 минут, пока ставится и выкатывается): случай «бот назвал
  цену, которой нет» и чем кончился; почему личный аккаунт автоматизировать нельзя; откуда
  берутся метки источника в ссылке и зачем они в заявке.

## Домашка

**Минимум — это и есть сдача, срок три дня:**

1. Дозаполнить `03-цены`, `05-стоп-темы`, `07-воронка`.
2. Прогнать десять вопросов из `eval.json`.
3. Живой диалог с чужого аккаунта до заявки.
4. Прислать **четыре скриншота**: вывод `check.sh` целиком; диалог не меньше чем из пяти ваших
   сообщений, среди них обязательно «сколько стоит?», «сделайте скидку» и вопрос про то, чего у
   вас нет; оповещение-заявку, как она пришла в телефон; свой `03-цены.md`, где видно, в каких
   строках стоит «да».

Третий и четвёртый скриншоты вместе и проверяют главное: что бот не назвал неподтверждённую
цифру. Сверяется «да» в таблице с цифрами в диалоге.

**Дальше, срок неделя:** файлы 01, 02, 04, 06; все двадцать четыре вопроса; десять живых фраз
в голос.

**Ссылку клиентам не даём, пока домашка не сдана.**

Чинить при ошибках нужно **базу**, а не бота. Это главная мысль домашки.

## Что пойдёт не так: ответы заранее

| Что случится | Почему | Что сказать |
|---|---|---|
| `claude: command not found` на сервере | нет node | бутстрап из допуска 2 |
| «Are you sure you want to continue connecting?» | первое подключение к серверу | напечатать `yes` целиком |
| «У меня Pro, агент не стартует» | на Pro нет Opus | пересоздать с `--model sonnet` |
| Служба зелёная, бот молчит | нет токена подписки или не подтверждено окно при старте | `check.sh`, пункт 0 |
| Бот отвечает мне, но не клиенту | политика доступа не `open` | установщик кладёт её сам; проверить `access.json` |
| Добавила в группу — молчит | включена приватность бота | `/setprivacy` → Disable и **заново добавить** в группу |
| Оповещения не приходят | нет второго бота или своего id | допуск 3 и блок 0:17 |
| Выкатываю — ругается на метки | база не заполнена | это защита: без фактов агент выдумывает |
| `409 Conflict` в логе | тот же токен слушает кто-то ещё | один токен — один потребитель |
| Username бота занят | бывает | добавить город; имя потом меняется, username — никогда |
| MAX не даёт создать бота | нужен верифицированный профиль ИП или юрлица РФ | остаёмся на Telegram |

## Чего на уроке не делаем

- **Не трогаем чужих ботов и чужие токены.** Один токен — один бот, один потребитель.
- **Не подключаем личный аккаунт.** Отвечать за человека в его личке запрещено правилами
  площадок, аккаунт блокируют. Для лички — отдельная история: агент читает и готовит
  черновики, отправляет человек.
- **Не выпускаем на клиентов в день урока.** Сначала домашка и тест.
- **Не обещаем Instagram и ВКонтакте.** Instagram — только через агрегатора с официальным API;
  канала ВК в навыке пока нет.
