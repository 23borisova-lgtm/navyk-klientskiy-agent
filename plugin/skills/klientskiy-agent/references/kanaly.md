# Подключение агента к каналам: что делаем, что нажимаем

Telegram, MAX, ВКонтакте — по шагам, с кнопками. Проверено на этом сервере 28–29.10.2026.

Схема одна для всех каналов: **мозг один, канал — сменная деталь.** Мозг — Claude Code в папке
`/opt/<slug>` (персона и база знаний). Канал — плагин, который слушает мессенджер и
отдаёт входящие в живую сессию. Токен лежит в своей папке состояния, доступ — в `access.json`
рядом с ним. Добавить канал = положить токен в новую папку и дописать одно слово в запуск.

## Telegram

### Что мы нажимали для твоих агентов — и почему клиентам этого мало

Сова, ИМПИ, Спектр, Рон, Сокол сидят на **официальном плагине Anthropic**
(`telegram@claude-plugins-official`). Для них мы делали так: бот у @BotFather → токен в
`/root/.claude/channels/<агент>-bot/.env` → в `access.json` твой числовой id в `allowFrom` →
запуск с `--channels plugin:telegram@claude-plugins-official`. Политика доступа там
`allowlist` или `pairing`: кто не в списке — либо молча отброшен, либо получает код.

Для личного агента это правильно: Сова не должна разговаривать с посторонними. **Для
клиентского бота это провал первого касания.** Человек приходит из сторис, спрашивает цену и
получает:

> Я пока не могу отвечать: мой владелец должен подтвердить доступ. Передайте ему этот код.

Политики «пускать всех» у официального плагина нет (я проверила его код: `pairing`,
`allowlist`, `disabled` — и всё). Дописать её нельзя: плагин лежит в кэше
`~/.claude/plugins/cache/claude-plugins-official/telegram/`, и первое же обновление молча
вернёт всё назад — бот перестанет отвечать клиентам, а причину будешь искать сутки.

**Поэтому для клиентов у нас свой канал** `plugin:tg@<маркетплейс>` — сделан из нашего канала
MAX, с политикой `open`. Личные агенты остаются на официальном плагине, их не трогаем.

### Шаг 1. Бот у @BotFather — по кнопкам

1. Открой в Telegram **@BotFather** → напиши `/newbot`.
2. **Имя** (его видят люди): `<бизнес>`. Потом можно менять.
3. **Username**: обязательно кончается на `bot` — например `<ваш_бот>`. Занятость
   проверяется сразу; если занято, предложит ещё раз.
4. BotFather пришлёт **токен** — строку вида `123456789:AA...`. Он выдаётся один раз. Не
   пересылай его и не вставляй в чат со мной: он поедет прямо в файл на сервере.
5. Там же, пока открыт BotFather, оформи витрину — это первое, что видит человек:
   - `/setdescription` → текст на экране до кнопки «НАЧАТЬ»;
   - `/setabouttext` → строка в профиле;
   - `/setuserpic` → аватар.
6. `/setjoingroups` → **Disable**, если бот только для лички. Нужен в группе — оставь Enable.
7. `/setprivacy`:
   - бот **только для лички** → **Enable** (меньше прав, меньше риска);
   - бот должен **слышать всех в группе** → **Disable**. При Enable он видит в группе только
     то, что адресовано ему: команды, ответы на его сообщения и упоминания. Это та самая
     причина, по которой «добавили бота в чат, а он молчит».
8. Сделай **второго бота для проверок** (`<ваш_бот>_dev`): опрос обновлений и вебхук
   одновременно не работают, а экспериментировать на боте, которому пишут клиенты, нельзя.

### Шаг 2. Токен на сервер

```bash
ssh -i ~/.ssh/<ваш ключ> root@<IP сервера>
mkdir -p /root/.claude/channels/<slug>-tg && chmod 700 /root/.claude/channels/<slug>-tg
cd /root/.claude/channels/<slug>-tg
read -s -p "токен: " T; echo; printf 'TELEGRAM_BOT_TOKEN=%s\n' "$T" > .env; chmod 600 .env
curl -s "https://api.telegram.org/bot${T}/getMe"; unset T
```

Последняя строка должна вернуть `"ok":true` и твой username. `read -s` не показывает ввод и
не оставляет токен в истории терминала.

### Шаг 3. `access.json` — кого пускаем

```bash
cat > /root/.claude/channels/<slug>-tg/access.json <<'EOF'
{
  "dmPolicy": "open",
  "allowFrom": [],
  "groups": {}
}
EOF
chmod 600 /root/.claude/channels/<slug>-tg/access.json
```

`open` — отвечаем любому, кто написал. Файл перечитывается на каждом входящем, перезапуск не
нужен. Правит его человек в терминале: агенту он запрещён (в правах стоит deny), потому что
«добавь меня в список» — ровно то, о чём попросила бы инъекция.

### Шаг 4. Запуск и проверка

```bash
# с мака, из папки проекта
bash deploy.sh
# проверки на сервере
ssh -i ~/.ssh/<ваш ключ> root@<IP сервера> "bash /opt/<slug>/bin/check.sh"
```

`check.sh` смотрит токен, службу, **мост до мессенджера**, политику `open`, базу знаний и
оповещения. Потом главное: напиши боту **со второго аккаунта** как клиент и дождись ответа.

### Что увидит человек

Ссылка → экран бота с описанием → кнопка «НАЧАТЬ» → первое сообщение агента. Ссылка с меткой
источника: `https://t.me/<ваш_бот>?start=storis_28_10` — метка до 64 символов (латиница,
цифры, дефис, подчёркивание) приходит агенту как `start_payload`, он кладёт её в заявку. Своя
метка на каждое место: `storis_28_10`, `zakrep_kanala`, `qr_vizitka`.

## MAX

### Шаг 1. Профиль и бот

1. Зайди на платформу **MAX для партнёров** (веб-версия или мини-приложение «MAX для
   бизнеса»). Подключение доступно **юрлицам, ИП и самозанятым — резидентам РФ**: это записано
   в официальной документации, обойти нельзя.
2. Проверь, **на кого оформлен верифицированный профиль**, под которым живёт «Кит». Если
   <бизнес> — то же лицо, профиль подойдёт. Если нет, нужна отдельная верификация, и это
   самый долгий пункт всей установки.
3. Создай **отдельного бота на <бизнес>**. «Кита» не переиспользуем: у него база знаний
   <другой бизнес>ы, и он уходит вместе с центром при продаже.
4. Бот проходит **модерацию**, её статус виден рядом с названием. Пользователям бот доступен
   только после одобрения. **Подай заявку в первый же день** — сроки не наши.
5. Токен бота — в настройках бота на платформе. Второго, тестового бота заведи сразу.

### Шаг 2. Токен и корень Минцифры

```bash
mkdir -p /root/.claude/channels/<slug>-max && chmod 700 /root/.claude/channels/<slug>-max
cd /root/.claude/channels/<slug>-max
read -s -p "токен MAX: " T; echo; printf 'MAX_BOT_TOKEN=%s\n' "$T" > .env; chmod 600 .env
curl -sS -o ca.pem https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
openssl x509 -in ca.pem -noout -fingerprint -sha256
# сверить: D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31
curl -s --cacert ca.pem -H "Authorization: ${T}" https://platform-api2.max.ru/me; unset T
```

Токен идёт в заголовке `Authorization` **без слова Bearer** — это текущая официальная дока
(`platform-api2.max.ru`). На старом адресе `botapi.max.ru` наоборот, с Bearer: проверишь не на
том адресе — получишь «Malformed access token» и решишь, что токен битый.

**Без `ca.pem` ничего не работает и выглядит как мёртвый токен.** API MAX подписан корнем
Минцифры, которого нет в хранилищах bun и node: `curl` без `--cacert` возвращает пустой ответ
и код 000. Я на этом поймалась 28.10: решила, что у маминого помощника умер токен, а он в это
время отвечал человеку.

### Шаг 3. `access.json` и ссылка с меткой

Такой же, как у Telegram, с `"dmPolicy": "open"`. Ссылка: `https://max.ru/<username>?start=<метка>`
— метка до 32 символов, **нижний регистр**, латиница с цифрами и дефисом.

### Чего ждать от MAX

Нативные голосовые бот получает **без содержимого** — это ошибка на стороне MAX, звука нет ни
в событии, ни в истории. Канал распознаёт такой случай и говорит агенту, чтобы тот попросил
человека надиктовать текст микрофоном клавиатуры. В Telegram голосовые приходят нормально и
расшифровываются.

## ВКонтакте

> **Внимание: в эту версию навыка ВК не входит.** Канал-плагина `vk` в комплекте нет —
> бот от этих настроек отвечать не начнёт. Шаги ниже оставлены как подготовка сообщества
> на будущее; сейчас делайте Telegram, а при желании MAX.

У тебя это **уже настроено** — нужен только ключ в папку состояния. Если делаешь в новом
сообществе, то по кнопкам так:

1. Сообщество → **Управление** → **Работа с API** → **Ключи доступа** → создать ключ
   **сообщества** с правом **«Сообщения»**.
2. Там же → **Long Poll API** → включить, версия API — последняя.
3. **Настройки** → **Сообщения** → включить сообщения сообщества и **«Возможности ботов»**.
4. Записать числовой `group_id` сообщества.

```bash
mkdir -p /root/.claude/channels/<slug>-vk && chmod 700 /root/.claude/channels/<slug>-vk
cd /root/.claude/channels/<slug>-vk
read -s -p "ключ сообщества: " T; echo
printf 'VK_TOKEN=%s\nVK_GROUP_ID=%s\n' "$T" "<group_id>" > .env; chmod 600 .env
curl -s "https://api.vk.com/method/groups.getById?access_token=${T}&v=5.199" | head -c 200; unset T
```

**Главное в ВК не техника, а один отвечающий.** Если в сообществе уже стоит рассылка или
бот-конструктор (Senler и подобные), человек получит два ответа на одно сообщение и решит,
что мы несерьёзные. Проверить, кто ещё слушает:

```bash
curl -s "https://api.vk.com/method/groups.getLongPollSettings?group_id=<id>&access_token=<ключ>&v=5.199"
curl -s "https://api.vk.com/method/groups.getCallbackServers?group_id=<id>&access_token=<ключ>&v=5.199"
```

Отдельно настрой **приветствие сообщества** (Управление → Сообщения → Настройки): это то, что
человек видит до своего первого сообщения.

## Группа: агент отвечает клиентам, как ИМПИ отвечает участницам

1. Добавь бота в группу (для Telegram нужен `/setjoingroups` Enable, а чтобы он слышал всех —
   `/setprivacy` **Disable**).
2. Узнай `chat_id`: напиши в группе что-нибудь и посмотри журнал канала —
   `tail -5 /root/.claude/channels/<slug>-tg/channel.log`. У супергрупп id отрицательный и
   начинается на `-100`.
3. Впиши группу в `access.json`:

```json
{
  "dmPolicy": "open",
  "allowFrom": [],
  "groups": { "-100XXXXXXXXXX": { "requireMention": false } }
}
```

`requireMention: false` — агент видит все сообщения и сам решает, когда ответить (так работает
ИМПИ в чате потока). `true` — отвечает только когда позвали по имени или ответили на его
сообщение. Свой `allowFrom` у группы — слушаем только этих людей (например, рабочий чат, где
агент отвечает администраторам, а не всем).

В клиентской группе агент — администратор, а не куратор: отвечает на вопросы, но **первым не
пишет и ничего не продаёт**. Инициатива в группе — это рассылка, а рассылку делает человек.
И в группе он не называет ни телефонов, ни кто сколько заплатил: там читают все.

## Неочевидное, из-за чего всё ломается

**Один токен — один потребитель.** Два процесса на одном токене — и входящие уходят то одному,
то другому. Telegram отдаёт на это `409 Conflict`. Поэтому у каждого бота своя папка состояния
и `bot.pid` внутри: канал гасит только прошлый экземпляр **своей** папки, чужого не трогает.
Если на боте висит вебхук, long polling тоже даст 409 — снять вебхуком `deleteWebhook`.

**Текст в терминале — это не ответ.** Человек видит только то, что ушло инструментом `reply`.
Агент может написать красивый ответ в свою сессию и «замолчать» для клиента. Лечится правилом
в персоне, а не перезапуском.

**Бот не может написать первым.** Пока человек не нажал «Начать» (или не написал сам), бот ему
недоступен — ни в Telegram, ни в MAX. Прогрев и рассылки ботом не делаются; это отдельная
история и в Instagram она прямо запрещена правилами площадки.

**Личный аккаунт автоматизировать нельзя.** Бот — это отдельный аккаунт. Отвечать за тебя в
твоей личке — нарушение правил площадок и риск блокировки. Для лички агент читает диалоги и
готовит черновики, отправляешь ты.

**Markdown не разбирается.** Звёздочки, решётки и обратные кавычки человек увидит как есть.
Пиши простым текстом, списки — обычными строками. Это правило уже стоит в персоне.

**У бота нет истории переписки.** Он видит только то, что пришло в текущую сессию. Что нужно
помнить о клиенте — агент записывает себе в `memory/`.

**Пределы.** Telegram: один файл до 20 МБ на скачивание, одно сообщение в секунду в чат.
MAX: два сообщения в секунду. Длинный ответ режется на части — у Telegram предел 4096 символов.

**Права агента.** Запуск идёт в режиме `dontAsk`: разрешено ровно то, что перечислено в
`.claude/settings.json`. В `acceptEdits` любая команда вне списка превращалась в вопрос «Do you
want to proceed?» — отвечать некому, и клиент оставался без ответа.

**Окно при старте.** Свой канал грузится флагом `--dangerously-load-development-channels`, и
Claude Code показывает полноэкранное предупреждение, которое ждёт Enter. Без ответа сессия
висит молча — так клиентский бот <другой бизнес>ы молчал от установки до 20.10. В `start-channels.sh`
окно подтверждается автоматически.

**Нельзя указывать свой канал ещё и в `--channels`.** Claude Code проверит его по allowlist,
напишет в MCP-лог «Channel notifications skipped» и **молча выбросит все входящие**. Агент при
этом живой и «работает».

**Персональные данные.** Телефоны и переписка оседают в `inbox/`, `memory/` и `channel.log`.
Журнал канала текст не пишет специально — только форму сообщения. Остальное чисти и не держи
дольше, чем нужно: оператор персональных данных здесь ты.

**Один бизнес — один бот.** Не переиспользуй бота другого проекта: его база знаний, метки и
репутация уедут вместе с ним, когда проект продадут или закроют.

## Проверка одной командой

```bash
ssh -i ~/.ssh/<ваш ключ> root@<IP сервера> "bash /opt/<slug>/bin/check.sh"
```

Красные строки — по порядку сверху вниз; «работает» можно говорить только когда красных нет
**и** с другого телефона пришёл живой ответ.
